# emotion_laptop

桌面的数据收集和结果显示

## 关键功能
1. 数据的读取和显示
2. 数据的分类和继承等。
3. 界面的Flutter化，尽可能少插件使用，或者说自己做插件。


## 实现规则
1. 插件尽可能封装成自己的Wrapper，方便后续替换和维护。
2. 数据的读取和显示分离，数据的读取通过服务来实现，数据
3. 数据存储在本地，从云端读取的话也是只存本地，只有主动点击上传才可以云端有数据更新。


## Getting Started

主要是用作桌面端的功能，所以是app的一种基础使用逻辑。
核心目的：快速的实现功能，完整的理解flutter逻辑，优化到可以自己做Flutter插件的程度。


# 功能框架
## 需求描述
整体是桌面风格，所以就按照顶部有导航栏的传统显示方式，通过导航栏来切换不同的功能。
主页面：整体风格用左侧小，右侧大进行区分，左侧类似摘要，右侧类似Chart显示。
设置页面：设置服务器地址，设置数据获取频次，设置权限开启（例如获取键盘和鼠标等的输入事件）等。
元素查看：可以查看当前记录的数据逐个查看并且修改/删除。
心态收集器：除了后面做模型，还是要考虑主动收集用户的情绪状态，方便优化模型，衡量情绪的指标：心率，睡眠质量，运动量，情绪分类。



1. APP运行后有一个界面显示当前运行数据，或者加载中。
2. app可以静默｜低占用的运行在后端，但是留有一个Icon在系统的托盘区，最好做一个类似活动的动画，到时候研究。
3. 托盘区icon直接打开主界面，不做二级菜单。
4. 开启运行的主要任务是创建一个持续采集数据的任务，并且在有数据更新的情况下，用户点击主界面会邀请输入情绪指标，每一个都不是必选项，所以可以快速跳过（或者5s不填写也会自动关闭）。
5. 每个数据都是独立的，全部依靠一致的分析方法。
6. 支持在桌面端创建一个局域网的Socket服务器，手机端可以搜描当前wifi网络下的服务器，链接后可以进行文字传输和文件传输。
7. 对于是否数据上传到开发者的服务器是一个默认关闭的选项，开启后会在每次开始运行才传输或者主动点击上传两种情况。
8. 在开启上传的情况下，会在云端统计周围的共同的用户情绪状态（这里只同步分析后的结果，基于网络能获取到的GPS位置粗略评估周围10Km的用户）的情绪状态，给用户一个参考。
9. 使用Flutter的AI能力，做一定的AI功能，当前如果要使用的话，需要用户自己填写的API Key，或者说自己搭建一个AI服务器。
10. 简单，低占用，轻社交，保护隐私，保护用户情绪。
11. 内置一个默认关闭，但是开启后会在第一次键盘敲击后的45分钟屏幕逐渐类似侵入式的提醒用户休息一下，保护眼睛和身体健康。
